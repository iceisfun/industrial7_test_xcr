# CPU SIMD and Extended Processor State - owner guidance (verbatim summary)

Purpose: guidance for a general-purpose Windows CPU feature and extended-state test repository. NOT a statement of work: a collection of test ideas for a well-configured OS. Result must be usable on ordinary Windows 10/11; Industrial7 (a from-scratch OS running Windows executables) is just another test environment and must NOT be embedded in the test logic. Largely comes from the author's own (model) knowledge of x86, Windows and the ABI. Generic, "Windows-like" C programs; inline asm is fine.

Scope: portable Windows .exe tests covering x87, MMX, XMM, SSE, SSE2-SSE4.2, AVX, AVX2, FMA, AVX-512, XSAVE/XRSTOR, XCR0, thread contexts, exception handling, simple perf benchmarks.

## 1. Standalone .exe programs
cpu_features (CPUID leaves, vendor, family/model, OSXSAVE) | xcr0_probe (XGETBV, XCR0 consistency, enabled XSTATE components) | xstate_windows (Windows XSTATE APIs, feature masks) | xsave_roundtrip (XSAVE/XRSTOR with legal masks) | xmm_registers (XMM0-15 patterns/preservation) | ymm_registers (YMM upper/lower lanes) | zmm_registers (ZMM, opmask, conditional) | sse_arithmetic (SSE..SSE4.2 arithmetic/integer) | avx_arithmetic (AVX, AVX2, FMA, edge cases) | fp_environment (MXCSR, rounding, FTZ/DAZ, FP exceptions) | thread_xstate (per-thread SIMD isolation, yields, sync) | context_xstate (Get/SetThreadContext and extended state) | exception_xstate (SEH, vectored handlers, register preservation) | fiber_xstate (fiber switching and FP state) | alignment (aligned/unaligned loads/stores, page boundary) | simd_memory (MOVNT*, cache flush, fences, masked memory access) | simd_dispatch (runtime detection and fallback) | simd_crypto (AES-NI, PCLMULQDQ, SHA ext) | simd_jpeg (scalar/SSE2/AVX2 JPEG decoder output comparison) | simd_bench (scalar/SSE/AVX throughput/latency) | xstate_stress (many-thread contamination, context-switch stress) | feature_faults (unsupported instruction and disabled-state fault behavior).
Each independently executable, meaningful exit code, short human-readable summary PLUS machine-readable output. Feature unavailable on host => SKIP, not FAIL. Feature advertised but failing to execute correctly => FAIL.

## 2. Processor feature consistency (agreement of physical CPU, enabled OS state, Windows API reporting)
- CPUID leaf 0, 1, 7 and extended leaves; enumerate subleaves, not just subleaf 0.
- CPUID leaf 0xD: supported XSTATE components, sizes, offsets, XSAVE capabilities (XSAVEOPT/XSAVEC/XGETBV ECX=1/XSAVES, compacted format).
- AVX hardware support separately from OSXSAVE and XCR0. AVX eligibility needs XCR0 bits 1 and 2. AVX-512 eligibility needs XCR0 bits 1,2,5,6,7 plus CPUID feature bits.
- Compare native XCR0 with GetEnabledXStateFeatures(), accounting for the API's reporting semantics. Query GetXStateFeaturesMask() on properly initialized CONTEXT. IsProcessorFeaturePresent() consistent with actual instruction execution, without assuming every CPUID extension has a PF constant.
- Behaviour under CPUs/VMs with AVX/AVX-512 disabled or hidden. XGETBV only attempted when supported and OS enabled XSAVE (OSXSAVE). Separate XCR0 (user-managed state) from IA32_XSS (supervisor XSTATE components).
- Check GetEnabledXStateFeatures, InitializeContext, GetXStateFeaturesMask, LocateXStateFeature, SetXStateFeaturesMask against documented contracts.
- An OS can have working AVX2 execution while Windows extended-context APIs remain incomplete: report these as SEPARATE results.

## 3. Userland tests
Register state and scheduling: fill XMM/YMM/ZMM with distinctive nonzero patterns, verify after forced scheduling (Sleep(0), SwitchToThread, waits, mutex contention, events, migration); 2,16,64,256,1024 worker threads where resources permit; per-thread pattern to detect leakage; state survives blocking syscalls; after creating/terminating many threads; nested calls, callbacks, DLL calls, thread-pool callbacks; fibers with and without FIBER_FLAG_FLOAT_SWITCH vs native behaviour; ABI: Windows x64 preserves low 128 bits of XMM6-XMM15 across calls, upper YMM portions are volatile; x86 and x64 separately, WOW64 context tests when applicable. Use assembly helpers or controlled intrinsics: ordinary C variables do not pin hardware registers.
Windows XSTATE context: initialize XSTATE-aware CONTEXT via supported APIs; buffer-size negotiation and alignment; GetThreadContext on suspended worker; modify eligible state with SetThreadContext, resume, inspect; CopyContext and compare XSTATE contents; LocateXStateFeature enabled and unsupported features; active masks, initialized vs modified components; invalid feature masks and undersized buffers return documented errors rather than corrupting memory; x87 control word and MXCSR survive context operations; debug-register requests separate from FP/vector requests. Include NEGATIVE tests for parameter validation.
Exceptions: deliberate integer exceptions while SIMD regs hold known patterns; SEH and vectored handlers; guard-page and access violations; deliberately unsupported instructions under controlled handling; FP control/status after exceptions; recovery from masked and unmasked FP exceptions; RaiseException, RtlCaptureContext; setjmp/longjmp and C++ exceptions testing only ABI-required preservation; compare reported exception context against an instruction-level reference helper. Intentional illegal-instruction / memory-fault tests run in CHILD PROCESSES.

## 4. SIMD math correctness
Categories: integer arithmetic (add/sub/mul/saturating); FP (add, sub, mul, div, sqrt); permutations (shuffle, blend, insert, extract, permute); comparisons (eq, gt/lt, ordered/unordered); bit ops (and/or/xor/shifts/popcnt); FMA (rounding and exceptional cases); conversions (int<->float, signed/unsigned, packing); SSE4.2 string compares, CRC32C; memory (aligned, unaligned, masked, streaming). Inputs: zeros, negative zeros, infinities, NaNs, denormals, min/max integers, rounding boundaries, saturation. Compare exact bits where the spec is exact; tolerance where implementation-dependent (rcpps/rsqrtps approximations) and keep original bit patterns in diagnostics. AVX-to-SSE transition test: AVX instrs, call SSE-only routine, back to AVX.

## 5. Benchmarks (simple; PERF, no pass/fail)
Array add GB/s scalar/SSE2/AVX2/AVX-512; int multiply M ops/s; FP ops/s scalar/SSE/AVX/FMA; dot product; matmul GFLOPS; memcpy/memset CRT/SSE2/AVX2 GB/s; CRC32C software/SSE4.2; AES blocks software/AES-NI; JPEG decode MPix/s; RGB/YUV conversion; thread state stress iterations/s; context capture normal/XSTATE ops/s. QueryPerformanceCounter for time, optional RDTSC/RDTSCP diagnostic (do not assume TSC==core cycles). Warm-up, median+variability across iterations, defeat dead-code elimination, large inputs, cache-resident vs bandwidth, pin thread, record affinity/frequency/feature flags, verify correctness before accepting a number, same exe and inputs on Windows and Industrial7. AVX-512 may lower clock: slower result is not necessarily an OS defect.

## 6. Real-world decoder tests (optional programs)
libjpeg-turbo scalar/SSE2/AVX2; libpng/zlib; stb_image as independent reference; simple YCbCr->RGBA converter scalar + SIMD. Input corpus: 8x8 and 16x16, 4K and 8K, grayscale/RGB/subsampled, progressive and baseline, odd dimensions and strides, partially corrupt/truncated, repeated multithreaded decode. Compare checksums of fully decoded buffers with identical output formats. Decodes-successfully-but-wrong-pixels is a FAIL. Hardware media-engine decode is separate from CPU AVX.

## 7. Negative tests
Unsupported instruction only in isolated exception-handled test; expected illegal-instruction exceptions; unsupported XSTATE feature bits to Windows APIs; invalid/inconsistent context flags; unaligned buffers where alignment required; SIMD access at the end of a committed page with adjacent page uncommitted/protected; masked instructions must not access inactive lanes (fault suppression guarantee); SIMD state from one thread never appears in another; new thread gets expected initial FP environment (MXCSR 0x1F80, x87 CW 0x27F on x64 Windows - verify); MMX/x87 interactions, EMMS requirement.

## 8. Repository organization
simd-tests/ common/{cpuid.c, feature_detect.c, timing.c, report.c, test_helpers.c}; tests/*.c (one per exe); benchmarks/{simd_bench,memory_bench,context_bench,jpeg_bench}.c; corpus/{jpeg,reference_vectors}; scripts/{run_all.ps1, compare_results.py}; README.md; CMakeLists.txt. Prefer MSVC and clang-cl compatibility, arch-specific asm helpers as needed. Baseline executables must NOT require AVX instructions to start; never compile the whole runner with /arch:AVX2 - use per-function target attributes / separate objects.

## 9. Result classification
PASS, FAIL, SKIP (capability absent), XFAIL (documented expected failure), CRASH (unexpected termination), TIMEOUT, PERF (measurement only). Record for differential testing: exe version, compiler, host CPU, CPUID flags, XCR0, OS build, process architecture, duration, exit status. Store raw outputs; summarize deviations; distinguish functional mismatches from performance differences.

## 10. Further areas
(1) Extended-state preservation across callbacks and transitions matters more than endless AVX2 arithmetic: register patterns around exceptions, blocking waits, context APIs, thread switches. (2) Optional extended-state features enabled on demand: Windows 11 GetThreadEnabledXStateFeatures() and EnableProcessOptionalXStateFeatures() (AMX etc) - optional tests on newer systems. (3) Hardware vs OS-reported feature disagreement (esp. Windows executables over another kernel): never assume Windows API reporting and native CPUID/XGETBV agree; record the discrepancy and determine if it causes an actual compatibility failure.

## Priority order
1 CPUID/XCR0/Windows XSTATE API reporting. 2 XMM/YMM round-trip. 3 ABI nonvolatile preservation and multi-thread isolation. 4 exception/context capture+restore. 5 SIMD math with reference vectors. 6 real-world JPEG decoder comparison. 7 small repeatable scalar/SSE2/AVX2 perf comparisons.
Guiding principle: TEST THE OS CONTRACT, NOT THE PROCESSOR IMPLEMENTATION. The same exe should show a feature is available, works, state survives OS-mediated operations, and apps can use it without corrupting data. Goal: general Windows CPU-state conformance and diagnostic suite for compat layers, hypervisors, emulators and native OSes.
